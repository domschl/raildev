# AGENTS.md — Raildev 3D Development Guide

This document captures the architecture, design direction, technical invariants, and workflows for **Raildev 3D** so agents (and humans) can seamlessly continue development—especially as development moves to a higher-memory **x86_64 + Nvidia GPU** workstation.

---

## 1. Project Vision & Direction

**Raildev 3D** is a European railway management & simulation game built in **Godot 4.7+ (Forward+ / Vulkan)**, licensed under **MIT** (see [LICENSE](LICENSE) and [ATTRIBUTION.md](ATTRIBUTION.md)).

### Core Visual & Gameplay Pillars
1. **Seamless Dual-Regime Scale (Continental Atlas ↔ Street-Level Diorama)**:
   - **Overview / Strategic Zoom**: Real continental Europe topography + Sentinel-2 Cloudless satellite imagery paired with a crisp 2D cartographic railway overlay ([RailMapOverlay.gd](godot/scripts/RailMapOverlay.gd)) so tracks, stations, and trains stay readable across all of Europe.
   - **Close-Up Diorama Zoom**: Smoothly crossfades from blurry 40 m/px satellite pixels into **100% crisp, normal-mapped, stochastic PBR ground textures** (cobblestone streets, meadow grass, woodland floor, geological Alpine rock & snow), populated by GPU-instanced **2-tier LOD dense 3D forests** ([VegetationStreamer.gd](godot/scripts/VegetationStreamer.gd)), **streaming European city buildings + station forecourts** ([UrbanStreamer.gd](godot/scripts/UrbanStreamer.gd)), and **micro-scale textured railways & steam trains** ([RailwaySystem.gd](godot/scripts/RailwaySystem.gd)).
2. **Real-World Railway Engineering & Signaling**:
   - Single- and double-track spline building with automatic bridges, Alpine tunnels (with rock-hooded stone masonry portals), Y-junctions/crossovers, 1-track and upgradeable **2-track passing stations**, block/one-way/chain signaling, realistic `1x` train speeds (`55–160 km/h`) with `1x/15x/60x/300x` sim speeds, and a **Follow Train** chase camera.
3. **High-Res Regional Realism Packs**:
   - Modular regional insets (currently `zugspitze` at ~40 m/px and `pyrenees` at ~80 m/px) that blend high-resolution DEM, Sentinel-2 albedo, pixel-accurate OSM water masks (`*_water.png`), and offline landuse masks (`*_landuse.png`: R=forest, G=urban, B=roads) into the continental map.

### Hardware Transition Context (x86_64 + Nvidia GPU)
Earlier development targeted an Apple M2 Max (Arch Linux ARM / `aarch64`), keeping detail bubbles, texture sizes (`512×512`), mesh polycounts, and regional pack slots conservative. Moving to a **high-memory x86_64 + Nvidia workstation** unlocks richer graphics:
- Larger close-up streaming bubbles (`BUBBLE_RADIUS` in `VegetationStreamer.gd` and `UrbanStreamer.gd`) and higher `MultiMesh` instance budgets.
- Higher-resolution PBR textures (`1024×1024` or `2048×2048`) and richer multi-LOD architectural/rolling-stock `.glb` models (historic station landmarks, cathedrals, bridges with stone arches, animated locomotive wheels/rods, more European building styles).
- Advanced Forward+ lighting & atmosphere (SSAO, SSIL/SDFGI, volumetric fog, dynamic time-of-day / weather, crisp shadow cascades).
- Additional high-resolution regional realism packs (e.g., Swiss Alps, Rhine Valley, London–Paris, Northern Italy) and expanding `EuropeWorld.gd` beyond 2 concurrent pack shader slots (or using a `Texture2DArray` / clipmap atlas).

## 3. Critical Technical Invariants (Read Before Editing!)

### Scale & Metric Harmony
- World size: `WORLD_SIZE = Vector2(204.8, 153.6)`, `KM_PER_UNIT = 15.0`.
- Harmonized micro-scale constants in [RailwaySystem.gd](godot/scripts/RailwaySystem.gd):
  - `STATION_SCALE = 0.019`, `STATION_HALF_LEN = 0.024`
  - `DOUBLE_TRACK_OFFSET = 0.012`, 2-track station platform lateral slot offset `±0.006`
  - `TRAIN_SCALE = 0.016`, `CARRIAGE_SPACING = 0.021`
  - Train vertical railhead offset: `+0.0014` (sits flush on railheads and clears station canopy roofs); station internal edge height: `wy + 0.0002`.
  - Spatial junction protection & collision radii are coupled to `DOUBLE_TRACK_OFFSET` (`0.010` / `0.0075` / `0.008`). **Never change `DOUBLE_TRACK_OFFSET` without updating those thresholds and re-running `--sim-test`.**

### Grounding & Elevation Consistency
- **GPU vs CPU Terrain Interpolation**: The terrain shader uses **Cubic B-Spline** interpolation while CPU `sample_elevation_m()` uses bilinear interpolation. On convex hills/slopes, these can differ slightly:
  - All 3D buildings and trees MUST have underground roots/plinths (`y = -0.38` to `-0.45` in `tools/generate_3d_assets.py`) and be sunk slightly (`-0.0020` to `-0.0025`) so they never float.
  - Track smoothing in `preview_track()` enforces `maxf(sm, clearance_y[i])` with a deep ballast skirt (`drop_y = -0.009`) so terrain never pokes through rails.
- **Continuous Track Exclusion**: `RailwaySystem.is_near_railway()` uses continuous segment distance (`Geometry2D.get_closest_point_to_segment`) with a cached per-edge `_aabb` (invalidated in `split_edge_at_t()`). Do not revert to vertex-only checks, or trees/houses will spawn in the gaps between spline vertices.

### Terrain & PBR Shader Conventions
- **Close-Up Ground Synthesis**: Above `cam_dist = 5.2`, `europe_terrain.gdshader` shows pure Sentinel-2 satellite imagery. Below `5.2 → 1.45`, it crossfades into 100% crisp PBR textures using `sample_stochastic()` (4-corner hash-rotated `textureGrad` sampling) so there is zero visible tiling repetition on meadows, woodland floors, or Alpine rock.
- **Shadow Acne vs Micro-Shadows**: `EuropeWorld.gd` dynamically adapts directional shadow cascades to camera distance (`shadow_bias` clamped to `>= 0.008`, `shadow_normal_bias >= 0.18`). Going lower than `0.008` causes wavy moiré stripes on flat terrain.
- **Camera Pitch Tilt on Mountains**: `AtlasCamera.gd` clamps `target_pitch_offset` directly inside `_clamp_pitch_offset()` (preventing dead-zone wind-up) and lifts `look_target.y` proportionally when terrain clearance pushes the camera up on steep slopes.

## 4. Setup & Asset Pipeline (Moving to a New Machine)

Large baked terrain binaries and regional packs are excluded by `.gitignore`:
- `godot/data/*.f32`, `*.rgba`, `*.jpg`, `*.png`
- `godot/data/packs/`

When setting up on the new x86_64 + Nvidia workstation, either **copy `godot/data/` directly** from the previous machine OR regenerate them via the Python scripts (using `uv` or a venv with `numpy`, `pillow`, `requests`):

```bash
# 1. Regenerate procedural 3D .glb assets (pure Python stdlib)
python3 tools/generate_3d_assets.py

# 2. Regenerate seamless PBR albedo + normal textures (requires numpy + pillow)
uv run --with numpy --with pillow python3 tools/generate_pbr_textures.py

# 3. Bake continental Europe topography + Sentinel-2 albedo (if not copied)
uv run --with numpy --with pillow --with requests python3 tools/enrich_europe_topography.py

# 4. Bake high-res regional realism packs (if not copied)
uv run --with numpy --with pillow --with requests python3 tools/bake_region_pack.py --region zugspitze
uv run --with numpy --with pillow --with requests python3 tools/bake_region_pack.py --region pyrenees
```

## 5. Verification & Testing Workflows

Always verify changes before committing—never claim visual or simulation fixes without running the relevant check.

> **Executable name & GPU offload**:
> - On **Arch x86_64** (distro package), the Godot 4 binary is `godot`. On **aarch64** (self-built Godot 4 where the distro's default `godot` was v3), it is `godot4`.
> - On dual-GPU workstations where the monitor is attached to the Intel iGPU and the Nvidia GPU is offloaded, prefix graphical runs with `prime-run` (from `nvidia-prime`).

1. **Visual Regression Screenshots** (renders Munich micro-scale station/city, Alpine peaks/forests, and overview shots):
   ```bash
   # x86_64 Arch (with Intel display + Nvidia PRIME offload):
   prime-run godot --path godot -- --visual-test /tmp/raildev_shots
   # aarch64 (self-built Godot 4):
   godot4 --path godot -- --visual-test /tmp/raildev_shots
   ```
   Inspect `shot_micro_station.png` and `shot_alpine_forest.png` to verify shader compilation, grounding, textures, shadows, and track clearance.

2. **Headless Railway Simulation & Signaling Stress Test** (12,000 steps, 6 trains, Y-junctions & chords):
   ```bash
   godot --headless --path godot -- --sim-test   # or `godot4` on aarch64
   ```
   Must pass with **0 collisions**, **0 signals in junctions**, **0 sharp/180° turns**, and **0 deadlocks** (`end_wait=0`).
